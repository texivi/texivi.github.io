Subverge / Handbook

Tabs

Subverge has four tabs. Each is a complete omega session with its own stack, definitions and screen, and all four run at the same time. Tabs are the only form of concurrency, and there are always exactly four.

Switching

F1 to F4 and Alt-1 to Alt-4 show tab 1 to 4. A click on a tab title in the top bar does the same if a PS/2 mouse is present (ps2). The system handles these keys itself, so they work even when every tab is busy, and they are the way out of a program that does not answer Ctrl-C.

Switching shows the tab you chose in the window that has the keyboard, which is the whole screen until you split it. The tab looks exactly as you left it, including anything it printed while it was hidden.

Windows

The screen can show up to four tabs at once, each in its own window. Every window has a title line at the bottom with the number and title of its tab, and the window that has the keyboard is highlighted.

Key Action
Super-Enter opens a window
Super-W closes the window that has the keyboard
Super-arrows move to the window in that direction
C-x 3 opens a window beside this one
C-x 2 opens a window below this one
C-x 1 keeps only this window
C-x 0 closes this window
C-x o moves to the next window

A click in a window moves you to it. F1 to F4 and Alt-1 to Alt-4 show that tab in the window that has the keyboard, or move to the window that already shows it.

Super-Enter splits the window that has the keyboard in half and gives the new window to the lowest-numbered tab that is not on the screen, preferring the one that was in front last. If the window is wider than it is tall (counting a character as twice as tall as it is wide) the split goes side by side, and otherwise it goes one above the other. The new window gets the keyboard.

Closing a window hides its tab and gives the space to the next window. The tab keeps running and keeps its screen. With four windows open there is no tab left to show, so Super-Enter does nothing.

A tab is as big as its window. size gives the width and height in characters, the prompt wraps at the width of the window, and the page viewer, the editor and dired lay themselves out again when the size changes. Output that is wider than the window is cut off at the edge and comes back when the window grows. Programs that draw at fixed places, such as the games, expect 80 by 24 and show only the part that fits, so give them the whole screen with C-x 1.

The Super key is the Windows key. If your desktop uses it for its own shortcuts, QEMU never sees it unless QEMU has grabbed the keyboard. The C-x keys work without it.

What each tab has

Each tab has its own:

  • world: its stack and its definitions;
  • back history of 64 worlds;
  • prompt history of 16 lines;
  • key queue. Keys go to the tab in front only;
  • screen of up to 80 by 24 characters, with its own cursor and colour;
  • title, shown in the tab bar;
  • editor state, so scrawl can be open in two tabs at once;
  • stack for the kernel, 256 KiB, used by the interpreter and anything it calls.

The tabs share root, the memory of the system, the hardware and the disk. A root edit made in one tab shows up in all four as soon as it builds. A definition made at the prompt of one tab is visible only in that tab, and it replaces a root word of the same name there (names).

The tab bar

The top row is the tab bar. It shows the number and title of each tab, highlights the visible one, and shows the time on the right. It is redrawn once a second and on every switch. A * after the title of a tab means the tab has written to its screen since you last looked at it. If a long job runs in tab 2 while you work in tab 1, a * on tab 2 means it finished, failed or printed progress.

Working with tabs from omega

mytab .              this tab's number, 1 to 4
"build" title        renames this tab in the tab bar
2 tab .              [ "omega" "waiting for keys" 0 ]

tab gives a list with the title of the tab, its state and whether it is visible. The state is running for the tab that asks, or waiting for keys, sleeping or ready.

These words number the tabs from 1, to match the keys that select them. Everything else in omega counts from 0.

Titles are not saved. Every tab starts as omega after a reboot. Programs such as top set their own title while they run and put omega back when they end.

Running things in parallel

You can start a long job in one tab and keep working in another. Press F2 and type:

0 100000000 [ 1 + ] times .

Then press F1 and run top. While tab 2 is computing, top shows it as ready, and the idle percentage drops. When the result is printed, tab 2 gets a * in its title.

The tabs share one processor. The scheduler switches between the tabs that are ready 100 times a second, so two busy tabs get about half each. A tab that waits for a key, or sleeps with sleep or waitkey, uses no processor time at all.

A tab keeps its data to itself. The only place that all four tabs read from is root, so values that every tab should see belong in a root unit.

A way to use them

Nothing ties a tab to a job, but a layout like this works well:

Tab Use
1 the prompt you work at
2 long computations, such as mandel or a big bignum
3 scrawl on the root unit you are editing
4 top or clock, left running

Every tab has its own definitions, so tab 1 can try a new version of a word while tab 3 still has the old one. When the new version works, put it in root with 'name open, and all four tabs use it.

Titles in programs

A full-screen program usually sets the title when it starts and puts omega back when it ends, so the tab bar shows what each tab is doing:

[ "busy" title
  3 [ "working" say 100 sleep ] times
  "omega" title
] :job

If the program fails halfway, the title stays as it was, because titles are not part of the world and are not undone. clock and top work this way, and 'clock see shows how.

Stopping a tab

Ctrl-C stops the line that is running in the front tab, with the error interrupted, and the line is undone. Every built-in loop and the interpreter check for it between steps.

A line can still ignore Ctrl-C, for example when it is stuck inside one long built-in word. In that case, switch to another tab and leave it. A stuck tab does not stop the others. One tab cannot stop another, but reboot in any tab restarts the machine. On an installed disk this is safe, because every finished line has already been saved.

Faults

If the code in a tab makes the processor report an error, for example by reading an address above the 4 GiB that the system maps, only that tab is affected. It starts again at its prompt, reports the fault and says that the last line was dropped, and its world is the same as before the line. The other tabs do not notice.

Startup

At boot, each tab loads its saved world if Subverge is installed. Tab 1 then runs startup, which shows the system information and asks the first-boot questions (startup). Tabs 2 to 4 start at an empty prompt.
