Subverge / Handbook

World

A "world" is everything omega remembers about one tab: its stack and the definitions you made in it. Transactions, back and saving all work on worlds. A line gives the tab a new world or leaves it as it was, back returns to an older world, and saving writes the current world to disk.

What a world holds

  • The stack, every value on it, bottom to top.
  • The definitions made in the tab with :name, edit or forget, newest first.

Each of the four tabs has its own world.

Kept outside a world

These are kept somewhere else and follow their own rules:

State Where it lives
root words root, shared by all tabs, edited with open
locals from { } and -> the running quote, gone when it finishes
the screen the tab's screen buffer, never undone
the tab's title the tab, reset on reboot
memory, ports, the CPU the machine, changed the moment a word runs
prompt history the tab, text only

A new world per line

A line starts from the current world of the tab and works on a copy. When the line is finished:

  • if it failed, the copy is thrown away and the world stays as it was;
  • if it worked and changed the stack or the definitions, the copy becomes the new world and the old one goes into the history;
  • if it worked without changing anything, it leaves no trace.

The history keeps the last 64 worlds, and back returns to them. A line that only prints or looks at something, such as words or top, does not add a world, so back skips it.

Keeping 64 old worlds takes little memory. Defining a word adds one entry in front of the existing definitions instead of copying them, so successive worlds share almost everything (how worlds work).

An example

Each line below either makes a new world or does not:

1 2                 new world: the stack is 1 2
[ dup dup * * ] :cube   new world: cube is defined
words               no new world, it only prints
3 cube              new world: the stack is 1 2 27
0 /                 fails, the world stays 1 2 27
back                returns to the world before 3 cube
back                returns to the world before cube was defined

After the two backs the stack is 1 2 and cube is gone. redo would bring cube back. words and the failed line never made a world, so back skipped them.

Looking at your world

words               every definition, with its value
depth .             how many values are on the stack
depth list .        the whole stack as one list
'sq see             one definition
stats               five numbers about the tab

words lists the newest definition of each name, and leaves out names that were removed with forget. A tab with nothing defined says so.

stats gives the number of live objects in the memory of the tab, how many garbage collections have run, the number of definition entries, the depth of the stack and the length of the history:

stats . . . . .

top shows the same numbers for the tab it runs in, and keeps them up to date.

Changing it

You add definitions with :name and remove them with forget:

[ dup * ] :sq
'sq forget

forget adds an entry that hides the name instead of deleting the old one, so back can still undo it, and a root word with the same name shows again (names). forget only works on names that were defined in the tab.

empty clears the stack in one step.

Worlds and saving

On an installed disk, the world is saved to the slot of the tab after every line that changes it. What is saved is the newest definition of each name and the stack, as omega source (saving). The history is not saved, so after a reboot the tab has its world but nothing to go back to.
