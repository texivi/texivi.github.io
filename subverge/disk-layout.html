Subverge / Handbook

Disk layout

An installed drive has no partitions and no file system. install writes the bootloader, the kernel and the saved state to fixed sectors, listed below, so an image can be read with a hex editor. Named values are kept in phi, which has a slot of its own.

The map

Sectors are 512 bytes.

LBA 0           MBR
LBA 1-16        stage 2
LBA 64          the kernel, as many sectors as it needs
LBA 8192        the state header, "SVSTATE1"
LBA 8193        slot 0, root, 2048 sectors
LBA 10241       slot 1, tab 1
LBA 12289       slot 2, tab 2
LBA 14337       slot 3, tab 3
LBA 16385       slot 4, tab 4
LBA 18433       slot 5, phi, 1024 sectors
LBA 19457       the end of everything Subverge uses

About 9.5 MiB in all. install refuses any drive smaller than 10M. Anything past the end is ignored.

The kernel gets the sectors from 64 up to 8191, which is just under 4 MiB. If a kernel you've built does not fit, install stops with an error. The current one is about 1.9 MB, most of it the help pages and the pictures.

The kernel copy

install does not write the running kernel. At boot, before anything else runs, the kernel copies its own .data section aside, and install writes the code from memory followed by that untouched copy of the data. So an installed kernel boots fresh, without whatever state the live system had built up, and without anything you poked into it.

The state header

The sector at LBA 8192 holds the marker SVSTATE1, the length and a checksum of each slot, the number of saves so far, the theme, the name of the logo and the length and checksum of the phi slot, which come after the logo name. If the marker is wrong, the header is treated as empty and every slot as unused. Disks installed before 0.9.0 have dusk as their theme, disks installed before 0.9.1 have no logo name, so sys draws the subverge logo, and disks installed before 0.9.6 have no phi slot, so phi starts empty. Disks installed before 0.9.6 keep their state header at LBA 4096 and are read only by the kernel they were installed with, so installing again moves a disk to this layout. A slot's data is written first and the header second, so a save that is interrupted leaves the old header pointing at a slot whose checksum no longer matches, and that slot starts fresh.

The slots

Each slot is 2048 sectors, 1 MiB, and holds plain omega source with a zero byte after it, padded to a whole sector. Slot 0 is root, every unit after its #>> name line. Slots 1 to 4 are the worlds of tabs 1 to 4. Slot 5 is phi, 1024 sectors, 512 KiB, in a text format that is described on its page. See saving for what is in them and when they're written.

A slot whose length is 0, too big, or whose checksum does not match is treated as empty.

Finding the home drive

At boot the kernel reads sector 1 of each of the four IDE drives, and the first one with SUBVERGE at byte 8 is home. If two drives both have Subverge installed, the first one is home and the other one is not used.

Looking at it

On the host, with the VM shut down:

$ dd if=disk.img bs=512 skip=8192 count=1 | xxd | head -4
$ dd if=disk.img bs=512 skip=10241 count=4 | strings

shows you the header and the start of tab 1's world. Do not write to the image while QEMU has it open.
