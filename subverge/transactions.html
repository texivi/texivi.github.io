Subverge / Handbook

Transactions

Every line runs as a transaction. If every word on the line succeeds, the line takes effect. If a word fails, the whole line is undone.

1 2 3
[ 7 ] :seven 4 5 0 /

The division fails. seven is not defined, 4 5 is not pushed, and the stack is still 1 2 3. What a transaction protects is the world of the tab: its stack and its definitions.

What a line is

A transaction is one line from the prompt and everything that runs because of it: every word, every quote and every program it starts. Running snake or learn is one line, however long it takes. If anything inside fails, the whole line fails.

The other things that run code have their own rules:

Code Rule
a line at the prompt one transaction
startup at boot one transaction in tab 1
a saved world at boot one transaction per tab
a root rebuild all or nothing, separately from any tab
a quote inside try continues the line on failure, without rolling back

What is protected

A transaction protects the world, which is the stack and the definitions of the tab. A failed line leaves both as they were.

Everything else happens the moment its word runs, and it stays done even when the line fails:

  • printed text stays on the screen;
  • anything drawn with put and text, and the title of the tab;
  • the machine itself: memory written with poke, ports written with out, memory taken with alloc;
  • root edits that have already been built;
  • the theme, the logo, and colours set with rgb;
  • the disk: a save happens after a line works, but install and save write while they run.

A program that changes the machine and then fails halfway leaves its changes in place. life frees its memory at the end, so if you stop it with Ctrl-C, the two boards it allocated are never freed.

Lines that change nothing

A line that leaves the stack and the definitions as they were, such as words or "hi" say, commits nothing. It does not go into the back history and nothing is written to disk. The system decides this by comparing the result with the world the line started from, so a line that pushes a value and drops it again also counts as unchanged.

Failing on purpose

Any failure ends the line, so a failure is also a way to cancel one. ask fails on Ctrl-C, and code that finds a problem halfway can stop with fail, which fails the line with a message you write:

[ { n } n 100 > [ "too big" fail ] when n 2 * ] :double-small
500 double-small
  ! too big

Nothing the line did to the world stays.

Continuing after a failure

try runs a quote and keeps a failure inside it from ending the line. It does not roll anything back: whatever the quote did before it failed stays done. See catching.

CPU faults

If the processor reports an error, such as a page fault from a bad peek, the tab restarts instead of just failing the line. The tab reports the fault and says that the last line was dropped, and its world is the one from before the line, because the line never committed. The other tabs carry on.

How it works

A line runs on a working copy of the stack and a pointer to the current definitions. Definitions are only ever added in front of the old ones, never changed in place, so the working copy shares everything with the committed world and takes almost no time to make. Committing the line means recording the new stack and the new start of the definitions as the current world. Failing means forgetting them. For the details, see how worlds work and the interpreter.
