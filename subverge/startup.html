Subverge / Handbook

Startup

At boot, tab 1 runs startup, defined in the sys unit of root. It prints the system information and the welcome hints. The other tabs start at a prompt.

What happens at boot

After the kernel has started, things happen in this order:

  1. Root is built, from the saved root on an installed disk or from the copy inside the kernel (how root builds).
  2. Each tab starts its shell. On an installed disk it first runs its saved world, so its definitions and stack are back before anything else happens.
  3. Tab 1 runs startup if it is defined, and sys if it is not.
  4. Every tab shows its prompt.

The saved world is loaded first, so startup can use words defined in tab 1, and a startup defined in tab 1 replaces the one in root.

startup runs as an ordinary line in tab 1. If it fails, the error is printed and the prompt appears as usual, and nothing it did is kept.

Changing it

'startup open

and edit the definition. [ sys ] :startup drops the hints, and [ ] :startup starts at a bare prompt.

'user open

changes the user in user@subverge. host, os and kernel-name set the other lines of the sys screen, and logo changes the drawing on the left (logos).

The hints

welcome prints a few lines of hints below the system information. They say whether the system runs from the live ISO or from an installed drive, and which words to start with. You can run welcome again at any time, and [ sys ] :startup leaves it out at boot.

Overriding it per tab

On an installed disk, the saved world of tab 1 is loaded before startup runs, and definitions in a tab come before root (names). Defining startup in tab 1 therefore replaces the root version without changing it:

[ "it's me again" say ] :startup

'startup see then shows your version in tab 1 and the root version in tab 2.

Missing startup

If startup is not defined, tab 1 runs sys instead. If root failed to build at boot, it shows a shorter version of sys and the root error in red.
