Subverge / Handbook

Saving

An installed Subverge saves after every line that changes something, without being asked, so a reboot or a power cut loses at most the line that was running.

The live ISO saves nothing. Run install first to keep your work. On the live ISO home gives -1, and save fails.

When saving happens

On an installed disk, these are saved right away:

  • A line that changed the world of a tab. Only the slot of that tab is written. A line that leaves the stack and the definitions as they were, such as words or "hi" say, writes nothing.
  • A back, because it changes the world back.
  • A root edit that builds. The whole of root is written to its slot. An edit that fails to build writes nothing (root).
  • A change to phi. The whole of phi is written to its slot.
  • A theme or logo change, which rewrites only the header sector (themes, logos).
  • install, which writes root, all four tabs, phi, the current theme and the current logo to the new drive.

save writes root, phi and all four tabs at once. You rarely need it, because everything is already saved, but it does no harm.

home gives the number of the drive that Subverge is installed on and saves to.

Slots

The saved state lives in five slots of 1 MiB at fixed places on the drive: slot 0 holds root and slots 1 to 4 hold the four tabs. A sixth slot of 512 KiB holds phi. A small header in front of them records the length and checksum of each slot and a count of saves. See disk layout for the exact positions.

Saving a tab rewrites only the slot of that tab and the header. The other slots are not touched.

What's in a slot

A slot holds plain omega source. A tab is written as its definitions, oldest first, followed by its stack on one line:

# saved world
[ dup * ] :sq2
[ { a b } a a * b b * + ] :hyp
"notes" :title
1 2 3

Only the newest definition of each name is written, and names removed with forget are left out, so the saved text is as short as it can be.

Root is written as the source of each unit after its #>> name header line, in order. This is the same format as the root/ files in the source tree.

At boot, the slot of root is built first. Then the slot of each tab is run as if it had been typed at the prompt of that tab. A saved world is therefore always one that omega can read back.

Values that survive

A value survives only if it can be written as source and read back. These can:

  • integers and bignums;
  • strings, with escapes for newlines, tabs, escape characters and the omega and aleph symbols;
  • quotes and lists, nested to any depth;
  • symbols ('name);
  • ordinals, written back as arithmetic such as omega 2 ^ omega +;
  • cardinals, written as 0 aleph or 2 0 aleph ^.

Two things change on the way. Identity is lost: two definitions that held the very same quote hold two equal quotes after a reboot (values and objects). And memory from alloc is not saved, so an address you kept on the stack points at whatever is in memory there after the reboot.

Not saved

  • the back history and the prompt history;
  • tab titles and screen contents;
  • memory from alloc, and anything written with poke or out;
  • the compiled code of the JIT, which is built again as code runs.

After a reboot every tab starts with an empty history, its saved stack and definitions, and the title omega.

Theme

The theme is saved with the system state and used at the next boot (themes).
