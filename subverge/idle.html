The idle loop

When no task can run, the kernel runs the idle task, which halts the CPU until the next interrupt. The next interrupt is at most ten milliseconds away, so an idle system uses almost no power and, in an emulator, almost none of the host CPU.

A task that waits for a key or a timer cannot run, so a system with every tab at its prompt is idle almost all of the time. The idle task runs whenever no other task is ready (scheduler).

Measuring it

The timer counts the ticks in which the processor was idle, and idle gives the count:

idle .

top divides the change since its last look by the change in all ticks to show a percentage. The figure is coarse, since it cannot see what happened inside a tick. It is good enough to tell a system that waits from one that works.

A shell in a tight loop makes the figure rise at once, and a shell at its prompt makes no difference. See interrupts for the timer and tools for top.
