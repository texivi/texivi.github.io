Subverge / Handbook

back

back undoes the last line that changed anything in your tab. What it restores is the world of the tab, which is its stack and its definitions. Each tab remembers its 64 most recent changes, so you can go back up to 64 lines.

Using it

Type back on a line of its own:

1 2 » 3
1 2 3 » [ dup dup * * ] :cube
1 2 3 » back
  rewound 1
1 2 3 »

cube is gone, and the stack is what it was before the line that defined it. Typing back again would also remove the 3.

back is a word like any other, so you can put several on one line:

back back back

rewinds three lines and says how many lines it went back. If fewer lines are recorded than you asked for, it rewinds as many as it can. If nothing is recorded, it tells you there is nothing to go back to.

Which lines count

Only lines that changed the stack or the definitions are recorded. A line that only printed something, such as words, help or "hi" say, leaves the world exactly as it was, so it is not recorded and back skips it. A failed line never changed the world in the first place (transactions), so it is not recorded either.

This means back always undoes something you can see. If you run top five times and then define a word, a single back removes the definition.

The rest of the line is discarded

A line that calls back commits nothing else. Whatever else it did to the stack or the definitions is thrown away, and the world is replaced by the older one:

[ 1 ] :x back

does not define x, and it rewinds the line before it. Put back on a line of its own, unless that is what you want.

Code that calls back inside a definition works the same way, so [ back ] :undo followed by undo rewinds one line.

redo

redo takes a back back:

1 2 » 3
1 2 3 » back
  rewound 1
1 2 » redo
  redone 1
1 2 3 »

Each back puts the world it leaves on a redo list, and redo takes worlds off that list again, newest first. redo redo redoes two. Like back, it throws away everything else on its line.

Any line that changes the world in a new way clears the redo list, because the worlds on it no longer follow from the current one. If there is nothing to redo, redo tells you so. A line with both back and redo only goes back.

The redo list holds up to 64 worlds and is not saved to disk, so it is empty after a reboot.

What back restores

back restores exactly what a transaction protects: the stack and the definitions of the tab. It cannot reach these:

  • Root. Root edits are separate and have their own rule for failures (root). To undo a root edit, open the unit and change it back.
  • Other tabs. Each tab has its own history, and back in one tab never affects another.
  • The machine. Memory written with poke, ports written with out, alloc, the screen, the title of the tab and the clock change the moment the word runs. back does not put them back.
  • Printed text stays on the screen.

Rewinding and saving

On an installed disk, a rewind is saved like any other change, so the world on disk after back is the older one (saving). The history itself is not saved. After a reboot each tab starts with an empty history, so the first back has nothing to go back to.

Cost

Rewinding is instant, however much is defined. A world is only a pointer to a stack and a pointer to the start of the definitions, and old worlds share almost all of their entries with new ones, so keeping 64 of them takes little memory. See how worlds work.

back and the Up arrow

The Up arrow at the prompt brings back the text of an earlier line. back undoes what a line did. To fix a wrong definition, back it, press Up twice to get the line back, edit it and press Enter.
