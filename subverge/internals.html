Subverge / Handbook

Internals

This page follows Subverge from the moment the machine is switched on to the moment the prompt appears, and then shows how the parts fit together while the system runs.

Boot, in order

  1. The ISO's GRUB, or an installed disk's own bootloader, loads the kernel at 1 MiB and jumps to it in 32-bit protected mode with Multiboot information.
  2. boot.asm builds an identity map of the first 4 GiB from 2 MiB pages, turns on PAE and long mode, loads a 64-bit GDT and calls kmain.
  3. kmain first copies the kernel's .data section aside, before anything's had a chance to change it, so that install can later write out a clean kernel.
  4. VGA, the font and palette, and the CPU tables come up: the IDT, the remapped PICs.
  5. The Multiboot info is read for the memory size, the memory map and the loader's name.
  6. The heap is set up after the kernel, up to 64 MiB.
  7. The scheduler, then persistence, which looks for an installed drive and reads it is state header.
  8. Every built-in word is registered, ordinals are initialised, and root is built from the units linked into the kernel, or from the root slot if there is one and it builds.
  9. Four tasks are started, one per tab, the PIT is set to 100 Hz, the keyboard and the mouse are turned on, and interrupts are enabled.
  10. kmain becomes the idle task, running hlt in a loop.

When each tab's task first runs, it loads it's saved world from its slot if there is one, tab 1 runs startup, and all four wait at a prompt.

Design

Most of the design follows from two decisions. Everything runs in ring 0 in a single address space, so the kernel and omega work on the same data structures directly. And nothing in an omega world is modified in place, which is what makes transactions, back and saving fast.
