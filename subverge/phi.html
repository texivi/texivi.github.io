Subverge / Handbook

phi

phi is the store for named values that are not definitions: notes, text, anything that needs a name and a place. It works like a small file system. Sets are directories, values are files, and a path such as /notes/todo names the value todo in the set notes. A value is a string. phi lives in memory, all four tabs share it, and an installed disk saves it. Subverge has no other file system.

A value written in one tab can be read in the others right away.

Looking at phi

"buy milk" "/notes/todo" phi-write
phi

phi prints the sets and values you made, indented by depth, and then the two sets that come with the system:

  /doc  112 read only
  /pictures  23 read only
notes                            1 member
  todo                           8 bytes

/doc holds the help pages, one value for each page. /pictures holds the built-in pictures as JPEG data. You cannot change either one or add anything to them.

Words

Word Effect
phi --, shows what phi holds
members path --, lists the members of a set, sets first
phi-names path -- l, the names of the members of a set, as a list
phi-read path -- s, the value at a path
phi-write s path --, stores a string, making the sets on the way
phi-set path --, makes an empty set
phi-delete path --, removes a value, or a set with everything in it
phi-move from to --, renames or moves a value or a set
phi-edit path --, edits a value in scrawl
phi? path -- n, 0 for nothing, 1 for a set, 2 for a value
dired --, browses phi
dired-at path --, browses phi starting at a set 
"/notes/todo" phi-read .
"buy milk"
"/notes" members
  todo                           8 bytes
"/notes/todo" "/notes/done" phi-move
"/notes/done" phi? .
2

If you write to a path that already has a value, the old value is replaced. If the set in the path does not exist yet, it is created. If the path goes through a value, or into a read-only set, the write fails and nothing changes:

"x" "/doc/new" phi-write
  ! phi-write: that set is read only

phi-edit opens the value in the editor, with the path as its name. Saving and quitting stores the text. Quitting without saving leaves the value as it was.

Paths

A path is a list of names separated by /. A leading / is optional, . means "here" and .. means "one set up". A name can have at most 31 characters, all of them printable ASCII, and no /. A path can go at most 16 sets deep and be at most 200 characters long. Names are compared exactly, including capital letters.

dired

dired shows one set at a time, with sets first. Next to each set it shows how many members it has, and next to each value its size. It also marks read only where that applies.

Key Action
C-n, C-p, n, p move the selection
RET, f, e open a set, or edit a value
^, DEL, u go up one set
+ make a set
c make a value and edit it
d delete the selection, after a question
R rename or move the selection
g read the set again
q, ESC leave

The questions are asked on the bottom row. You can edit a read-only value, but nothing is kept when the editor closes.

phi and the world

phi is shared by the four tabs, and it is not part of the world of a tab. If a line writes to phi and then fails, the write stays, because only the stack and the definitions are undone. back does not undo a write either. Keep values that belong to one tab in its world, and values that every tab should see in phi.

Using phi from a program

A value is always a string, so other kinds of values go in as text and come back out with a word that reads them. A number goes through str and >num:

42 str "/notes/n" phi-write
"/notes/n" phi-read >num 1 + .

prints 43. A list works the same way, because str writes it as source code and eval reads it back:

[ 1 2 3 ] str "/notes/l" phi-write
"/notes/l" phi-read eval len .

prints 3.

phi? tells a program whether a path exists before it reads or writes. phi-names gives the names of the members of a set as a list of strings:

"/notes" phi-names .

Size

phi can hold up to 480 KiB of values, counting the text of each one. A write that would go over that fails. The sets themselves use memory but are not counted.

Saving

On an installed disk, phi is saved after every change, in a place of its own, so it is still there after a reboot. The format is plain text: a line S and the path for each set, and a line A, the path and the length, followed by the bytes, for each value. A value can therefore contain anything, including line breaks. The slot is 512 KiB (disk layout). install and save write it too.

On the live ISO nothing is saved, and phi starts with only /doc and /pictures at every boot.

Disks installed before 0.9.6 have no place for phi. Their phi starts empty, and the first change creates it.
