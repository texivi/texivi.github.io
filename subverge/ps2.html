Subverge / Handbook

The PS/2 controller

The keyboard and the mouse sit behind the PS/2 controller, which has a channel for each. Data is on port 0x60, and status and commands are on port 0x64. A program has to wait until the controller is ready before it writes, and until a byte arrives before it reads. The kernel gives up if the controller never answers.

The keyboard

The keyboard sends scancodes of set 1. Each press sends one code and each release sends the same code with the top bit set (scancodes). The keyboard raises IRQ 1, and the handler reads exactly one byte each time, since the controller does not raise the interrupt again until the byte is taken (interrupts).

The mouse

The mouse raises IRQ 12. At boot the kernel turns on the second channel and asks the mouse to send packets of movement and buttons. A mouse that answers with a wheel gets four-byte packets, and one that does not gets three. If the mouse does not answer, the system runs without it and mouse? is 0 (mouse). The pointer is drawn on the text screen as an inverted cell.

The reset line

The controller also holds the line that resets the processor, and reboot pulses it (machine).

Real machines

Many machines have no PS/2 ports and emulate the controller for a USB keyboard and mouse. The emulation is often called legacy support and has to be turned on in the firmware. Where it is not there the system starts and cannot be typed at (why not more).
