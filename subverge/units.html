Subverge / Handbook

Units

A unit is a named part of root. Root is the code that every tab shares and that survives reboots, and units are how it is divided and edited. Words that should work everywhere belong in a unit.

Listing them

root prints every unit with its size and the words it defines:

A unit marked (draft) has an edit that failed to build and is waiting for you to fix it.

Making a unit

"mine" unit

creates an empty unit called mine at the end of root and opens it in scrawl. Write definitions in it the same way as at the prompt, one or more on each line:

# greetings
[ "hi" say ] :greet
[ { name } "hi, " name cat say ] :greet-name

Save with C-x C-s and quit with C-x C-c. The unit is built, and greet and greet-name exist in every tab at once. On an installed disk, root is saved right away.

To change it later:

'greet open

opens the unit that defines greet. open takes any word that the unit defines, or the name of the unit as a symbol, so 'mine open works too.

An example: your own logo

A logo has to be visible in tab 1 at boot, which makes it a good first unit:

"mylogo" unit

In scrawl, write:

# my sys logo
[ [ " /\\_/\\" " (o.o)" "  > <" ] ] :logo-fox

Save with C-x C-s and quit with C-x C-c. Then 'fox logo switches to it, and on an installed disk the next boot draws it too, because both the unit and the logo name are saved.

Rules for names

A unit name has 1 to 20 characters, which can be lowercase letters, digits and -, and it must be unique. Root can hold at most 32 units, including the 13 that come with Subverge.

Writing a unit

The source of a unit runs once, from top to bottom, every time root is built. It should be made of definitions. A unit can also work out values when it is built:

0 100 range [ sq ] map :squares

builds the list once, and squares then pushes it. Anything left on the stack at the end of a unit is thrown away.

A unit can see every word defined in the units before it, and every built-in. It cannot see definitions made at the prompt of a tab, because root is built outside the world of any one tab.

Comments are kept, because a unit is stored as the text you wrote. This is the main difference from 'name edit, which stores the code after it has been parsed.

Order and overriding

Units are built in order, and the definitions of each one go on top of everything before it. If two units define the same word, the later one wins for code that runs after root is built. Code in the earlier unit refers to the word by name, so it also sees the later definition when it runs.

A new unit is always added at the end. That means it can use every other unit, and editing it rebuilds only that unit, which is fast and cannot break the units before it.

If you define a word that is also a built-in, the build prints a warning with the name, in orange. The new definition replaces the built-in in every tab, even inside other root code, so you rarely want this.

Removing a unit

You cannot remove or reorder units from inside Subverge. To retire a unit, open it and delete its contents, which leaves an empty unit that defines nothing.

Tab definitions or a unit

Tab definition Unit
visible in one tab all four
made with :name at the prompt, 'name edit "name" unit, 'name open
undone by back editing it again
comments lost kept
failure the line is undone root is unchanged, the edit becomes a draft

A definition in a tab with the same name as a root word hides the root word in that tab only (names). This is a safe way to try a change before you put it in a unit.

A program that is listed in apps should be in a unit, together with its entry in the apps list.
